          Section 5: Database Access Protection
          
Firebase Security Rules & Initial Administrator Configuration

          

            Permissions are enforced directly inside Cloud Firestore Security Rules so that hiding buttons in the browser is never the only line of defence.
          

        


        

          

            

              Production firestore.rules
              
            

            
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isSignedIn() {
      return request.auth != null;
    }
    function isAdmin() {
      return isSignedIn() &&
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }

    match /users/{userId} {
      allow read: if isSignedIn() && (request.auth.uid == userId || isAdmin());
      // Prevent privilege escalation: new sign-ups must have role == 'employee'
      allow create: if isSignedIn()
        && request.auth.uid == userId
        && request.resource.data.role == 'employee';
      allow update: if isAdmin() || (
        isSignedIn() && request.auth.uid == userId
        && request.resource.data.role == resource.data.role
      );
      allow delete: if false;
    }

    match /tickets/{ticketDocId} {
      // Employees can ONLY read their own tickets; Admins can read ALL tickets
      allow read: if isSignedIn() && (
        resource.data.createdBy == request.auth.uid || isAdmin()
      );
      // Employees can create tickets only for themselves with status == 'Open'
      allow create: if isSignedIn()
        && request.resource.data.createdBy == request.auth.uid
        && request.resource.data.status == 'Open'
        && request.resource.data.resolutionNote == '';
      // ONLY Administrators can update priority, status, and resolutionNote
      allow update: if isAdmin()
        && request.resource.data.createdBy == resource.data.createdBy
        && request.resource.data.ticketId == resource.data.ticketId;
      allow delete: if false;
    }
  }
}

          


          

            

              
How Administrator Access is Initially Configured Securely

              

                When any user signs in for the first time through the web application, the client code and firestore.rules strictly force role: "employee". A normal user cannot send a request to make themselves an "admin" because the rule request.resource.data.role == 'employee' rejects it.
              

              

                To configure the initial Support Administrator safely, the project owner logs into the Firebase Console → Firestore Database → Data tab (which has project owner privileges), selects the designated administrator's document in the users collection, and manually changes the role field from "employee" to "admin".
              

            


            

              
Key Security Guarantees

              
• Zero Password Storage: Passwords are handled exclusively by Firebase Authentication and never written to Cloud Firestore.

              
• Row-Level Ownership Isolation: Even if an employee opens browser DevTools and runs a query for all tickets, Firestore checks resource.data.createdBy == request.auth.uid and rejects the query with PERMISSION_DENIED.

              
• Immutable Ownership: Even an administrator update cannot alter createdBy or ticketId.
